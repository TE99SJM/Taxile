# Setup reference

For an assisted setup, perform one numbered stage at a time and confirm it works
before proceeding. This document is a reference, not a requirement to do all
stages at once. The destination can remain undecided while preparing firmware.

1. **Identify and back up the device.** Connect by USB and identify its exact
   chip and Freematics revision. The included target is the original ESP32,
   UART-coprocessor ONE+, not ESP32-C3, AVR ONE, or an unverified SPI-only revision.
   Use the installed esptool's `chip_id` and `flash_id` commands on the selected
   COM port before writing anything. Save a full `read_flash` backup using the
   flash size reported by `flash_id`, rather than guessing 4 MB or 16 MB. Keep that
   backup private and off GitHub: it can contain existing credentials.

2. **Build and flash over USB.** Install PlatformIO Core 6.2.0 or the PlatformIO
   VS Code extension. Open the repository root, run `pio run`, then upload only
   after the hardware check with `pio run -t upload --upload-port COMx` (replace
   COMx). Monitor with `pio device monitor --baud 115200 --port COMx`. Use PlatformIO
   to flash all partitions at their correct offsets; do not write firmware.bin
   to address zero. Upload does not intentionally erase NVS, but back up first.

3. **Verify local recording.** Insert a FAT32 microSD with power removed. Plug into
   OBD with the vehicle safely parked. Read the unique setup password from USB
   serial. Join `Taxile-xxxxxx`, open `http://192.168.4.1`, and sign in as `admin`.
   Confirm SD ready, OBD connected and plausible RPM/speed. On an idle engine,
   zero speed must add no mileage. Set the clock from the phone if necessary.
   Do not proceed to unattended use with an SD or OBD error.

4. **Configure a destination.** For the included home-server option, put the repo
   on mserver, copy `.env.example` to `.env`, and replace the placeholder with a
   random token generated by `python3 -c "import secrets; print(secrets.token_urlsafe(32))"`.
   Keep `.env` private. Run `docker compose up -d --build`. Check `/health` from
   your home network. The existing mserver address previously used was
   `192.168.50.199`; verify it is still correct before using it. Reserve its DHCP
   address so the device endpoint stays stable. Port 8098 is only a proposed
   default; change the Compose host port if already in use. No router forwarding.

5. **Enter home Wi-Fi and receiver settings.** Wait until the device shows parked
   (two minutes without engine activity). In its setup page enter the 2.4 GHz
   home Wi-Fi name/password and receiver token. Example LAN endpoint:
   `http://192.168.50.199:8098/v1/batches`, with explicit LAN HTTP enabled. For
   HTTPS, use your actual HTTPS URL and its trusted root CA certificate. Save;
   the device restarts. The hotspot password persists. Credentials stay on the
   device and in the server's private configuration, not the code.

6. **Validate one trip and one retry.** Complete the vehicle checks in
   `VALIDATION.md` while parked for all phone/computer interactions. Confirm one
   trip reaches the receiver and an interrupted response does not duplicate it.

7. **Export reports when wanted.** Set `TAXILE_TOKEN` in your shell environment
   (same token as the receiver), then run:
   `python scripts/export.py http://192.168.50.199:8098 --out exports`.
   Open `daily.csv` or `trips.csv` in Excel. Files containing unknown timestamps
   retain their mileage in the summary's undated bucket. Choose and configure a
   Google Sheets or other adapter separately if desired.

## Troubleshooting

- **No SD:** check that it is FAT32 and properly seated with device power off.
  Never automatically format a card containing logs. The status fault is real;
  in-memory trip miles are not proof of saved mileage.
- **No OBD:** hardware link/revision and supported PIDs must be checked. The
  firmware never clears engine codes or writes vehicle settings.
- **No home Wi-Fi:** original ESP32 uses 2.4 GHz. Confirm SSID, password and signal
  from the parking spot. Failed uploads remain queued.
- **Hotspot gone:** it times out after ten minutes. USB serial `SETUP` plus newline
  reopens it when no trip is active. Avoid restarting midtrip solely for setup.
- **Clock not set:** use the phone button or internet-enabled NTP. HTTPS will wait
  for valid time. An internet-free LAN can still receive HTTP uploads, but you
  need a clock source to assign days accurately after total power loss.
- **Parked wake fails:** motion sensor detection and charging voltage vary by
  revision/vehicle. Verify before leaving it unattended. No guaranteed current
  draw or battery protection threshold has been established on your hardware.
- **Factory phone app no longer works:** this is independent custom firmware;
  it does not implement Freematics Controller's BLE protocol. Restore the backup
  if that factory behavior is needed.
